# 首版技术合同

2026-10-03。用户已授权开始开发；生产发布、收费和外部邮件尚未执行。

## 数据与权限

复用现有SQLite账户库，只新增pro_表。无需重写users.plan；权益以pro_entitlements的开始、结束、撤销状态每次重新计算。Cookie继续使用现有会话；Bearer验证哈希、用途、有效期和当前权益。网站账户管理只接受同源会话，Bearer只读。

内容ID和版本组合不可覆盖，依次draft → in_review → published。修订新增版本且必须填写更正说明；发布后旧版superseded；撤回不回退到旧版。运营身份和操作原因存pro_audit。审核人必须在原因中记录来源、条件、归属、时间精度、局限的检查结果。首版由受控CLI执行，无公共编辑或权益管理接口。

正式出版命令必须加载经manifest校验的PUBLIC_DATA_ROOT，验证厂商/模型/系列和归档证据ID。模型/系列标签还须有明确变化记录归属，不能从字符串猜测。服务方法还会检查结构、状态和版本，受控CLI增加实际数据门禁。

专业正文、表格和个人简报都存在账号服务数据库；静态页面只有UI。catalog公开的只是人工编写的preview；sample=true的内容明确完全公开。其他全文、导出、个人简报和私有RSS均使用private,no-store，不进入共享缓存。反向代理的/api/pro/禁用URL访问日志及普通错误日志，防止RSS URL凭证落盘。

## 端点

GET /api/pro/catalog：公开目录及预览，登录用户可取得自己的权益状态。
GET /api/pro/content/{id}：受保护全文；sample可匿名读取。format=markdown/csv导出。
GET /api/pro/me：本人权益、范围/邮件设置、个人简报索引、申请状态。
POST /api/pro/apply：本人使用场景申请，限500字，没有扣款。
POST /api/pro/settings：目录内对象并集、主题交集；至少一个对象。专业邮件独立开关。
GET /api/pro/report/{id}：仅本人的简报；format=markdown/csv导出。
GET /api/pro/tokens、POST /api/pro/token、POST /api/pro/revoke-token：会话管理凭证。
GET /api/pro/rss-address：取回当前私有RSS地址；会话与专业权益必需。
GET /api/pro/feed?token=…：仅RSS凭证；按当前范围输出已审核预览/链接，更正和撤回状态。
POST /api/pro/unsubscribe：以邮件fragment中的随机凭证独立退订，无需登录。
POST /api/pro/mcp：专业MCP独立端点，三个工具maas_pro_catalog、maas_pro_read、maas_pro_reports。

原/api/mcp继续只有原五个工具。原/api/v1、公共feed、免费每日提醒合同保持兼容。

401表示缺少或失效的登录/凭证；403表示权益未生效、到期/撤销或用途不允许；404不暴露别人的简报；服务缺配置/目录异常503；写操作校验Origin；所有路径有限流与请求大小上限。

## Token

通用凭证32字节随机值，默认30天，可1–365天，最多20个有效凭证；哈希存储，生成时只显示一次。RSS专用凭证可重新复制，AES-256-GCM加密存储，密钥由账户秘密按独立用途派生；轮换立即撤销旧RSS。两种凭证互不替用。不可写入提示词、公开仓库、通用Token URL或日志。账户秘密轮换须重新签发RSS地址，见operations。

## 简报与投递

周期ID为Asia/Shanghai周一日期，窗口[上周一00:00,本周一00:00)。只在运营明确组合时创建，不自动推断已完成全周覆盖。范围与选中版本存快照，每用户每周期仅一份；改范围不重写旧报告。读取时返回最新已审核版本及selectedVersion；撤回只显示状态。关键更正/撤回为已收到相关内容且仍订阅的账户创建独立更正任务。

pro_mail独立于免费mail_jobs，用户显式开启专业邮件才入队。不因后来开启邮件补发已有报告。投递前重新检查权益和开关，关停取消pending任务。消息第一次尝试后冻结以保持幂等；5分钟租约防并发，超过23小时的未确认尝试转review，须人工核对。邮件是有条件和证据的摘要，不承诺全文表格已在邮件中展示。实际收信需生产验收，适配器接受不等于收信。

## 导出与指标

Markdown包含期次、范围、版本、条件、来源；CSV保留结构化行和相同元数据，转义引号及电子表格公式前缀。来源时间保留日期精度。

pro_events记录目录、样例/正文/报告阅读、导出、申请及权益操作，用于30天聚合计数；不记录IP、凭证和邮件正文。metrics不把操作次数当作真实付费人数。编辑工时、业务使用和续付证据仍需试点运营记录。

## 回滚

发布前按现有账户SQLite一致性备份流程保存账号库。新增表对旧服务可忽略；回滚程序不会自动删表，不回写旧字段。必要时整库恢复须按现有运维流程验证，防止丢失回滚期间新增的免费账号数据。此阶段只准备部署配置，未安装定时任务或改生产数据库。
