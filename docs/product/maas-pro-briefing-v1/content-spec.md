# 专业情报内容规范

版本：0.0.1｜状态：待评审｜日期：2026-10-03。适用于首次样例制作及首版正式出版。

## 1. 三类内容及关联

统一编辑库保存重要变化详解和专题。每期周简报引用这些内容，按用户范围筛选组合，并保存范围快照、引用版本和覆盖状态。不以一人一篇自由生成文章作为首版生产方式。

| 内容 | 必需字段 | 可省略内容 |
| --- | --- | --- |
| 周简报 | 标题、期号、范围/主题、统计窗口、数据截至、出版时间、本周重点或无重点说明、分类清单、证据、覆盖限制、版本 | 没有新详解/新专题时不强制新增；说明相关项目为空 |
| 重要变化详解 | 事实摘要、前后对照、明确适用对象/条件、来源/观察时间、重要性理由、已确认与待核对项、关联记录、审核状态/版本 | 未观察到前值时说明，不能编造前值；无有效历史关联可留空 |
| 专题 | 要回答的问题、比较对象、时间/数据范围、比较口径、表格/时间线、结论、不可比项/缺失、证据、审核状态/版本 | 数据稀疏时用表格替代趋势图，不补点、不作预测 |

每条关键结论关联证据ID、来源URL和观察时间。出版时间、来源发布时间、生效时间和本站观察时间分别保存；未知字段标为未知。厂商身份、模型身份、模型系列和主题标签使用可审查映射，不能依靠标题猜测补模型ID。

## 2. 候选选择

### 2.1 首版主题

| 主题 | 合格事实 | 不合格推断 |
| --- | --- | --- |
| 价格 | 同条件金额变化，或新增有明确条件报价 | 新观察到价格等于刚刚降价；不同地区金额相减等于降价 |
| 计费条件 | 缓存、批处理、上下文、地区、档位或时间条件明确修改 | 官网删除一段文本就代表计费能力取消 |
| 模型生命周期 | 官方发布、版本/弃用/下线公告及明确日期 | 模型名消失就代表停服；参数相近就代表同一个模型 |
| 服务能力 | 官方明确的接口、配额或服务限制变化 | 参数声明等于实际性能改善；公告等于生产已全面可用 |

周期候选需去掉导航、排版、重复链接等噪声。多来源同一事件可合并，但保留各自证据、观察时间和差异，不抹平冲突。

### 2.2 入选重要变化的理由

至少具备一项可说明理由：金额或计费条件实质改变；官方明确的生命周期节点；已有选择范围内的接口/限制变化；有证据支持的跨平台相关调整。稿件需记录理由及依据。

优先顺序为事实可靠、与范围相关、适用条件明确、值得用户核对。低证据信息进入待核对区或留在公共普通动态，不能为了增加付费条目数提升其确定性。

## 3. 核验与可比性

- 优先利用已保存官方来源与证据。第三方榜单/评测只引用必要短摘与链接，先核对使用许可，不复制受限数据构建付费内容。
- 当前值来自接受的价格事实，历史值来自对应版本；明确“观察到变化”，只有官方确认才写“自某日生效”。
- 比较同一模型时确认实际API标识和版本；名称接近不自动合并。
- 对币种、单位、地区、档位、计费项、上下文、缓存、批处理及时间条件做一致性检查；不一致则分组或标为不可比。
- 同条件、前值大于0时可计算 `(后值－前值)/前值 × 100%`，使用原币种精确数值；前值为0/未知时只列值，不给百分比。
- 汇率换算标为估算并附汇率来源/日期，不用用户个人汇率生成所有人的公共研究结论。
- 无数据不是零，无记录不是未发生，缺测点不连成确定趋势；各主题覆盖分别说明。

## 4. 内容模板

### 4.1 周简报

```text
[期号] [标题]
关注范围 / 主题 / 统计窗口 / 数据截至 / 出版时间 / 修订状态

本周重点
- 事件、为何值得关注、事实明确程度

分类清单
- 价格 / 计费条件 / 生命周期 / 服务能力（按用户范围选入）

重要变化详解
- 事实摘要、前后对照、适用条件、来源

历史与横向对照
- 引用匹配的专题或已审核历史关联

待核对事项与覆盖限制
- 冲突、缺失、生效时间未知、采集失败

证据 / 关联阅读 / 更正与反馈入口
```

若统计窗口内未发现匹配的已核验重要变化，保留标题、范围、窗口、数据截至和覆盖说明，交付空期简报。采集失败时使用“本期覆盖受限”，不能使用全量“无变化”。

### 4.2 详解

先用一句话写已确认变化，再列前后值或条件；说明适用对象、历史关联、重要性理由、未确认部分。建议动作只限合理核对事项，例如核对供应商官方文档和合同适用条件，不直接要求迁移或承诺节省金额。

### 4.3 专题

先写问题与观察范围，再写比较口径，最后给对照表、时间线、结论与限制。同一模型跨平台对照不升级为跨模型质量排名。周期回顾不将信息数量当市场份额。

## 5. 编辑与发布

状态：draft → in_review → published；修改后形成新revision；无法支持主要事实时withdrawn。审核未通过退回draft，未解决项记录原因。

审核记录必须包括审核人、时间、来源/条件核对结果、模型归属、关键结论与证据对应、限制披露、允许公开的预览。单维护者可以兼任，但检查不能省略。

出版前检查：

1. 每条关键结论有依据；正文、表格、摘要和预览彼此一致。
2. 时间和比较口径明确，没有推断未归属模型或虚构历史。
3. 已过期来源/撤回引用已处理，冲突披露。
4. 用户范围只组合匹配内容，通用分析未混入个人资料。
5. 专业正文与独立公共预览分别发布，全文不能进入公开投影。
6. 记录出版版本并通过网站/查询/邮件/RSS一致性检查。

## 6. 更正与反馈

每次修订保存原因和影响范围；重大事实错误关联已引用该内容的简报并显示更正。更正通知按账户、报告、修订和类型去重，不把修改标题当新事件。

一般文字修订不重复发信；撤回保留可访问状态说明，不静默删除ID。允许用户提交原链接和问题描述，运营查看、确认和回复，不自动承诺固定小时响应。涉及公共基础事实的错误同步修正免费层。

## 7. 试点样例包

建议先制作3篇详解、2份专题、1期完整简报。其中至少1份专题体现不可比或历史缺失处理；实际事件不足时减量说明，不制造事件。完整样例从已审核内容明确选出，发布后仍可免费试读；其他正文按专业权益控制。

使用真实现有记录并复核证据，不在计划阶段把结构示例当真实报告。先验证样例质量和每期工时，再确定可销售覆盖范围。
