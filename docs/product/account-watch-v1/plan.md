# 账号与模型关注 v1

日期：2026-10-02。范围：邮箱验证码登录 → 关注模型 → 每日变化摘要与退订。

## 实施顺序

1. 独立 SQLite 持久库，用户、个人组织、免费权益、短期验证码、会话、关注、通知投递状态。数据库放 shared/state，跨 release/蓝绿槽位共享。
2. 同源私有 API `/api/account/`。验证码 10 分钟、5 次错误锁定、邮箱发送冷却与小时额度、IP 限流；验证码与 session 仅存 hash；HttpOnly/SameSite Cookie；写入校验 Origin；所有私有响应 no-store。
3. 我的关注页：登录/退出、搜索真实模型目录、增删关注、站内近期变化、主动勾选每日邮件、退订。只按明确 modelId 匹配，不推断未归属模型的变化。
4. 每日投递任务：首次关注不补发历史；每条记录版本去重；无变化不发；失败重试；投递幂等 key；可在未登录时通过邮件链接关闭邮件，GET 仅展示确认页，POST 执行。
5. 安全与功能集成测试、现有 API 回归、站点构建与页面验证；补部署说明。

## 取舍与边界

- 第一版只开放个人空间，后台保留个人组织和免费权益；团队邀请、收费、支付不在本次范围。
- 继续使用静态 Astro + Node API，避免切换整站渲染方式。
- 使用 Node 22 内置 SQLite（实验性接口），不引入数据库服务；WAL + busy_timeout + 短事务支持同机蓝绿。数据迁移仅增量，回滚代码不回滚用户数据。
- 邮件通过 Resend 适配器；本地可显式设置 outbox 模式，私密邮件只写忽略目录，不输出到接口/日志。生产不允许 outbox。
- 邮件服务未配置时展示明确不可用状态，不声称已发送。
- 数据中无 modelId 的平台变化不纳入模型提醒；当前并非覆盖全部新品、下线事件。
- 生产首次启用需数据库目录、邮件服务凭据和发件域名就绪。此处先完成可审查代码与部署候选，不把本地测试当作生产验证。

## 验收

- 同邮箱重新登录复用用户；验证码不可复用/过期/暴力猜测。
- 会话跨重启有效；退出后失效；另一账号不可读取或更改关注。
- 关注保存后刷新保留；未知模型拒绝；取消关注后停止该模型新通知。
- 邮件主动开启；无更新静默；重复执行不重复发；失败不吞通知；退订无需登录。
- 移动端、键盘、加载/错误/空状态可用，用户数据不进入公开投影。
