# 浏览器时区展示

精确时间按当前浏览器的 IANA 时区显示，时间文本包含 UTC 偏移，全站页脚标明时区。适用于登录与匿名访问，不根据网站语言推断时区，也不把一个设备的时区保存成其他设备的固定偏好。跨浏览器恢复账户配置不改变各设备的时间展示。

统一处理首页更新、价格台账更新与采集、模型价格观察/生效/最后成功、变化与修订、证据观察、跨平台比较、榜单抓取、账户建立时间。异步加载与刷新后使用相同规则，保留原始 ISO 时间在 datetime/tooltip 中。

仅日期精度的观察日、数据截止日、归档日期和榜单窗口保留原日期，不把 YYYY-MM-DD 当作 UTC 零点再换算。供应商的计费时段与来源时区保留，不随浏览器时区改写。无偏移的历史时间标明“时区未注明”，不猜测其来源时区。新的首页数据更新时间由采集/摘要脚本写入带 UTC 偏移的 ISO 值。

每日摘要任务仍固定在 Asia/Shanghai 09:15（UTC 01:15）。账户页同时说明固定规则并显示按浏览器时区换算的下一次检查日期、时间和偏移；按该日期的夏令时转换，每分钟及页面重新获得焦点时更新。有变化才发送，不承诺每位用户当地09:15收到邮件。

`node --test site/tests/time-display.test.mjs` 为统一回归门禁的一部分；`python3 scripts/timezone-browser-smoke.py` 在已构建站点上用虚构账户和真实 Chromium 复验，可复现截图与报告。

验证包括上海、洛杉矶、伦敦和 UTC+14 地区、跨日期和夏令时、日期精度不偏移、异步内容及中英文页面。证据见 acceptance。本次网站代码仍为本地候选，未执行网站生产发布；已有账号运维任务不受影响。

验收结果：时间转换与动态 DOM 测试4项、流水线输入测试6项通过；完整站点构建与最终重建通过（46,187页）；四个时区的真实 Chromium 验收通过，覆盖账户、价格、榜单、模型与跨平台比较、中文账户和手机宽度，无页面脚本错误。相关模型/价格/变化/多语言回归通过。
