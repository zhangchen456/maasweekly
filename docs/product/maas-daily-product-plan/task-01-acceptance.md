## R1 [P1] 缺失归档仍可构建成功，永久链接会整批失效

位置：`site/src/pages/item/[id].astro:10–20`、修订读取 `:27–36`；`site/package.json` 的 build 未接独立归档校验。

复现：复制站点到临时工程，保留 record-index（123 条）及 daily 数据，但不提供 data/records，执行正常 `npm run build`。

结果：退出码 **0**，成功生成 **31** 个原有页面，详情页 **0** 个。首页／周索引仍可保留指向详情的链接。

原因：详情路由和修订读取用空 catch 吞掉错误；所谓“构建前校验”只在 sync 中执行，纯 deploy 和 skip_fetch 路径不会经过它。

修复要求：

1. 将归档、索引、修订一致性校验接入实际 `npm run build` 或所有构建入口，不依赖先跑 sync。
2. 校验索引与归档双向完整性、ID／permalink／revision 等内容，不只比数量。
3. 读取损坏或缺失归档／修订时明确失败，禁止空 catch 生成半套页面。

复验：缺失目录、损坏单条记录、缺失索引、索引悬空、缺失修订五种情况下构建必须非零退出。正常输入仍成功。

## R2 [P1] 正常同步绕过输入错误，且未遵守“先校验再写入”

位置：`pipeline/scripts/sync-diff-to-site.py:134–164`；`archive-source-changes.py:67–98`。

复现 A：临时工程放入一个合法日期但 JSON 损坏的 diff，另放一个含未注册来源的 changed 记录，运行 sync.main。

结果：同步正常返回，归档 **0** 条，daily 中仍有 **无 ID** 的 changed 条目。损坏文件被跳过，映射失败只告警。

复现 B：同日输入连续两条相同 source_id，调用离线归档入口处理。

结果：第二条报冲突时，第一条已经落盘。sync 本身还缺少等价的同源重复检查。

修复要求：

1. 两个命令共用输入预检与归档计划，不维护两套不同规则。
2. 检查合法日期文件的 JSON、字段类型、业务日期、来源映射、同日身份冲突及已有归档；全部通过后再写。
3. 未映射、歧义、损坏输入均非零退出，不输出无稳定 ID 的“成功”站点数据。
4. 对 first_fetch、局部缺失、fetch_failed 保持不撤回规则。

复验：将错误记录放在已存在条目内容更新之后、第二个文件或列表末尾；失败前后归档与站点数据字节应一致。

## R3 [P1] 修订写入失败会先改坏当前记录，校验未检查修订内容

位置：`pipeline/scripts/record_archive.py:225–228`、merge/withdraw 中当前文件先于修订写入的逻辑；`validate_archive:381–386`。

复现 A：创建 r1，预先放置内容冲突的 r2 文件，再尝试更新记录。

结果：抛出拒绝覆盖异常，但当前记录已经变为 r2；当前内容和修订文件不一致。`validate_archive()` 仍返回 **[]**。

复现 B：把当前最新修订内容改成非法 JSON `{broken`，运行校验。

结果：仍返回 **[]**。校验只检查文件存在，没有解析内容或比较当前记录。

修复要求：

1. 写入顺序与预检保证失败时旧当前版本完好；处理中断可恢复重跑，不能形成不可修复的孤立状态。
2. 逐版本校验 JSON、身份、版本号、连续性，并验证最新修订与当前记录一致。
3. 更新与撤回使用相同的可靠写入机制。

复验：修订冲突、修订 JSON 损坏、版本内容不匹配、模拟写入中断时均能拒绝或恢复；不能报告一致性通过。

## R4 [P2] 独立回填会覆盖已有 LLM 摘要并制造重复修订

位置：`pipeline/scripts/archive-source-changes.py:89–98`；`record_archive.py:235–247`。

复现：归档一条来源记录，将已有 LLM 摘要作为 r2 保存，再对相同原始 diff 调用离线回填。

结果：摘要从 **llm 变为 rule**，revision 从 **2 变为 3**。用户按照文档重新回填会降级内容；之后 sync 再挂 LLM 摘要又会增加修订。

原因：摘要保留只在 sync 中特判，离线入口直接覆盖。现有 T07 单测把同一份含摘要对象再次 merge，未模拟缺少摘要的新输入。

修复要求：将“无新摘要输入保留已有值”的合并规则移至共用逻辑，区分未提供、显式更正和撤回。两个入口产生一致结果。

复验：sync → 离线归档 → sync 连续执行，输入不变时归档文件字节、摘要与 revision 均不变；覆盖窗口外历史和空摘要输入。

## R5 [P2] 仅由持久索引生成的旧周日期范围偏移一周

位置：`site/src/pages/daily/[week].astro:32–37`。

复现：使用代码现有日期算法计算 `2026-W36`。

结果：得到开始日期 **2026-09-07**，正确值为 **2026-08-31**。用“1 月 1 日加周数，再向后找周一”无法正确还原 ISO 周。

影响：目前两周都在 weekly-digest 中，所以正常构建测试没有触发；滚出近期窗口后才显示错误周范围，正好影响本任务必须保证的历史访问。

修复要求：使用 ISO 周一算法（1 月 4 日所在周为第一周），或从该周实际记录计算周一。索引独有周不能把缺失统计显示成已知的“0 项变化”；根据记录统计或明确不提供该统计。

复验：真正构建只存在于 record-index 的旧周页面，验证标题日期、记录日期和返回链接；覆盖 2026-W36、跨年 ISO 周和 65 日期滚动。
