# MaaS Daily SEO 整体优化方案

创建日期：2026-10-01（北京时间）。目标网站：https://daily.maas.click。
执行时间：2026-10-01 01:15（Asia/Shanghai）以后。此前只准备方案与调度，不修改站点实现。

## 目标与判断依据

通过模型 API 价格、平台比较和价格变化等具体问题，吸引有查询与选型需求的用户。以搜索展示、自然搜索点击，以及搜索访客查看模型、查询价格和订阅/接入的行为判断效果，不承诺排名或流量数量。

初步源码检查：站点已有独立 title/description 和 Astro 静态生成；共享 Layout 尚未看到页面级 canonical；未找到 sitemap/robots 配置；模型详情的核心价格和变化由浏览器请求 API，初始正文主要为加载占位。执行时重新检查当前版本和线上状态，不能将这些观察当作生产实测结论。

## 第一阶段：基线与技术基础（本次定时执行）

1. 阅读当前项目规则、合同、部署脚本和最新交接记录；检查分支、工作区、近期改动，保留他人的改动。核实线上首页、价格、模型、周报、robots、sitemap 的状态、重定向和响应内容。记录无法验证的项目。
2. 明确可索引页面：优先首页、价格页、具有实质内容的模型页、正式周报和有解释价值的变化详情。证据页及短小重复记录单独评估；不机械地为所有页面设置 noindex，也不把 API/筛选组合全部纳入 sitemap。
3. 为正式页面生成绝对 canonical，以当前正式域名和既有路由为准，统一尾斜杠策略，去除追踪参数。核实旧域名逐路径重定向；不要为 SEO 擅自更改稳定模型 ID、记录 ID 和对外链接。
4. 生成 sitemap 和 robots.txt，sitemap 仅包含可索引、成功响应的正式网址。lastmod 使用真实内容修改时间；缺乏可靠时间时省略。robots 不阻止必要渲染资源，不将 robots 当作禁止收录的替代方式。
5. 完善重点页的独立标题、摘要、H1 与站内链接。让标题明确表达模型 API 价格、价格变化或平台信息，避免堆词、无依据的最低价和排名声明。
6. 改进模型详情：复用当前经验证的 release 数据，在构建时输出有实际内容的价格、计费条件、来源、数据截至时间和最近变化；保留需要的交互和刷新。空数据如实说明，不编造价格，不绕过 release 一致性验证。
7. 仅在内容匹配时增加 WebSite、Article、BreadcrumbList 等结构化数据；不为了搜索展示添加无依据的评分、FAQ 或 Product 标记。结构化数据和社交分享元信息不是第一批交付的阻塞项。

## 第二阶段：重点搜索入口（本次选择并完成首批）

从当前数据中选择 3–5 个数据完整、来源可靠的模型或平台，优先完善现有模型页和价格入口，避免批量生成薄内容。每页回答：模型是什么、有哪些平台和可观察价格、输入/输出/缓存及适用计费条件、币种与单位、数据截至时间、近期变化与官方证据。

候选搜索方向：DeepSeek API 价格、同一模型不同平台的价格与计费条件、模型价格变化、模型调用成本。它们是待验证假设，不代表已经确认的搜索量。存在可靠数据和清晰比较口径时才制作比较页；成本计算器留作后续迭代，不扩大首批范围。

建立首页/价格页 → 模型页 → 变化/证据页的可抓取链接。链接文字说明目标内容。首页保持每日追踪定位，专题页承担长期查询问题。

## 第三阶段：内容与传播（后续持续迭代）

维护少量长期专题：API 价格比较口径、缓存/批处理/上下文计费说明、月度价格变化总结。每篇结合本站真实数据与官方来源，注明日期和方法。每日原始差异不直接批量转换为营销文章。

将有用的比较结果和变化图表分享到适合的开发者社区或内容渠道，链接到对应页面；此阶段先整理选题和分发清单，发布外部帖子需用户明确授权。

## 搜索平台接入与度量

准备 Google Search Console 验证和 sitemap 提交步骤；主要面向国内用户时增加百度搜索资源平台。使用现有可用账号和权限完成可执行部分；缺少登录、DNS 验证权限或验证码时记录具体待办，继续完成站点工作，不假称已经提交或收录。

沿用现有埋点事件和口径，核对自然搜索来源与模型详情、价格查询、订阅/Agent 接入行为是否可分析，确需新增事件再增加，避免重复 page_view。未接入 Search Console 前不猜测曝光、点击率和关键词排名。

上线后建议在第 7、14、28 天人工或另行授权自动复盘：索引问题、展示与点击、得到展示的查询词、落地页及有效行为。优先改善有展示但点击较低、或有点击但不能回答问题的页面。本次不自动创建额外周期监控。

## 验收与发布

- 对生成 HTML 检查唯一且正确的 canonical、独立标题/摘要、核心正文和可抓取内部链接；抽查首批模型的价格条件与源数据一致。
- 检查 sitemap XML、URL 去重和过滤、robots 指向、真实 lastmod、空数据行为以及查询参数处理；避免仅检查标签存在。
- 运行与改动相称的测试和构建；发布必须满足现有 release 链要求的全量检查，保留 REST/MCP/RSS/Skill 合同和埋点回归。
- 按现有授权与项目明确要求的审批阶段执行提交、发布与线上验收；不绕过生产专门确认规则。不因缺少搜索平台权限停下其余可完成工作。
- 交付改动清单、验证证据、已上线/仅本地的准确状态，以及具体的账号/验证待办。清理无用临时产物。更新本文档记录实际结果。
