# 项目用量基线与成本跟踪 v1（2026-11-02）

授权范围：用户确认先完成项目/基线，再接自动重算和每日邮件，完整验收后上线。Plus最多5个非归档项目（暂停仍保留名额），每项目1至10条实际用量。Free保留原工作区保存，项目页提供完整虚构样例。第一版仅普通输入/输出Token计费。

## 项目与基线

- 月输入、输出分别按每条实际模型/平台/完整计费条件填写，单位百万Token，最多6位小数。不同备选方案不自动相加。
- 从费用工具通过当前标签页sessionStorage导入；先选择一个实际方案，用户再主动添加其他实际用量。不将业务用量放进公开分享URL。
- 基线固定用量、报价条件/版本/来源/观察时间、汇率、展示币种及成本。修改用量/模型建立新版本，旧版本保留。不能把用户改用量标成供应商调价。
- 币种USD/CNY，汇率0.01–1000固定随基线保存。源报价币种/单位保留；使用BigInt十进制12位中间结果，最终展示再四舍五入。
- 输入/输出绑定相同模型、平台、源、计费模式、地区、档位、上下文、时段、单位和币种。按原绑定精确匹配，不按名称猜测，不自动取最低价。
- 创建与新基线保存必须是当前有效、唯一、证据完整报价；fresh状态另检查最近成功时间（或观察时间）不超过72小时。价格陈旧/缺失/歧义时拒绝建立新基线。
- 请求需网站会话和同源POST；身份和Plus权益由服务端读取。保存有请求幂等键、数据版本检查、基线版本冲突检查。报价/项目在确认前变化时409，要求重新预览。

## 私有接口（不属于公开机器API额度）

`GET /api/account/projects`：本人项目、当前Plus与邮件服务可用性。
`GET /api/account/projects/catalog`：当前输入/输出报价条件目录及数据版本，仍需登录。
`POST /api/account/projects/preview`：`{project}`，Plus预览，用量仍不持久化。
`POST /api/account/projects`：`{project,datasetVersion,requestKey}`，确认建立基线。
`GET /api/account/projects/:id`：本人详情、最新结果、最近50份基线和100条变化。
`POST /api/account/projects/:id/baseline`：增加`revision`，新建基线版本。
`POST /api/account/projects/:id/action`：`{action,revision,enabled?}`，pause/archive/resume/email。

只读已有项目与关闭/暂停操作允许Plus到期账户执行；新建/编辑/恢复/开启邮件要求有效Plus。未知/他人项目统一404；Bearer不能替代网站会话。响应private/no-store，不进入公开RSS或搜索索引。

## 自动重算

- API确认新数据版本激活后重算，候选加载失败时不计算候选数据。启动及每5分钟复查，用于到期/恢复与报价陈旧状态；09:15邮件任务发送前再以当前有效版本重算。
- 各条输入/输出按固定用量重算；相对当前基线和上次有效检查分别记录差额。
- 普通刷新、同价新观察不产生新变化；报价金额或可用状态变化才记录。缺失/陈旧/歧义条目cost=null，只汇总可计算部分，完整差额为null，不伪造降价。
- 暂停/归档/到期不自动重算。恢复检查最新报价，记录一份累计影响，不补发暂停期间旧邮件。旧基线的事件保持其原币种。

## 每日邮件

复用现有09:15 Asia/Shanghai任务、mail_jobs及MailLedger，不另设每用户定时任务。

- 项目邮件默认关闭，用户逐项目主动开启；不自动关注模型。开启前的历史事件不补发。
- 一账户一日一份项目批次，合并多个项目，只展示各项目最新变化；有普通模型汇总时合并同一未冻结队列任务。
- 项目已解释的同一价格事实不再重复列入普通变化；保留其他模型和非价格变化。
- 邮件包括项目名、预计金额、基线差额、前后原币种单价和详情链接；不附整份月用量表。
- 状态持续异常不重复发送；新变化/恢复发送一次。无变化不发。开启/关闭/暂停/到期/版本更新在投递前复核。
- 原退订链接明确关闭模型和项目汇总邮件；项目页可只关闭项目邮件。暂停或失去资格的无内容队列清理为cancelled。
- 供应商接收状态沿用已有审慎重试：超时unknown进入review，不假定失败并盲目重发。管理员明确可重试的拒收支持项目独立邮件。

## 范围边界

没有实际账单接入、缓存用量、包量优惠、税费、音视频等计费；不声明真实节省，不自动替换模型/平台。模型/报价消失仅称无法匹配，未验证不称官方下线。项目MCP、阈值、Webhook与团队协作后续再做。
