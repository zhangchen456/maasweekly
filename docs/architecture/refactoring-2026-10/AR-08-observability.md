# AR-08：运行指标与容量决策

状态：LOCAL_VERIFIED；基础和最终集成/容量均完成，见 AR-08-result.md；生产观测/真实工作流待发布验证。优先级：P1 基础、P2 完善。依赖：AR-01；随 AR-02/04/05 接入。

## 目标与边界

能判断数据是否新鲜、接口是否健康、发布是否变慢，并用证据决定何时扩容或更换查询存储。先采用结构化日志、现有 Nginx/systemd 与 CI 汇总，不部署新的大型监控平台。

Umami Cloud 继续负责访问与交互分析。本任务不建设自定义用户画像、原始访客事件仓库或新的 analytics 看板，也不修改已有 Cloud 统计口径。

交付指标定义、最小采集/汇总工具、告警规则、容量对比与 `AR-08-result.md`。

## 8A. 最小指标与关联字段

| 层 | 必需指标 | 关联字段 |
| --- | --- | --- |
| 抓取 | 成功/失败/未运行、耗时、重试、最后成功时间、解析数量变化 | runId、sourceId、extractorVersion |
| 数据 | fresh/stale/unknown、有效事实数、身份未解析数、证据完整度 | datasetVersion、sourceId |
| API | 请求量、P50/P95/P99、5xx/429/409、RSS/heap、事件循环延迟、数据加载耗时 | requestId、route、releaseId、datasetVersion |
| 构建发布 | 各阶段耗时、候选失败、激活结果、回滚、产物大小与文件数 | gitCommit、RID、datasetVersion |
| 存储 | 各类容量、增长、缓存命中/大小、恢复耗时 | 数据类别、采样时间 |

日志中的时间采用 UTC，用户报告按 Asia/Shanghai 展示。指标标签使用路由模板而非完整 URL/模型 ID/cursor，避免标签数量随实体无限增长；requestId 只用于日志关联，不作为聚合标签。

不记录 API key、cursor 原文、查询正文、复制内容或完整敏感 URL；日志传输失败不能阻断请求。sourceId 可用于受控信源统计，来源 URL query 不直接进入标签。

## 8B. 健康与新鲜度分开

分别描述：进程存活、数据就绪、当前数据新鲜程度。服务能返回 200 不代表全部来源 fresh；抓取失败继续服务旧版也不能直接判 API 不可用。

复用现有公开 status 的合理字段，内部诊断不要暴露绝对路径和内部异常细节。若新增内部 health/metrics 入口，明确访问范围与 Nginx 路由，不默认公开系统信息。

## 8C. 告警与恢复

在 AR-01 冻结的预算基础上设置阈值和恢复窗口。以下是待结合实际频率确定的初始规则：

- 日级来源连续 2 次失败或超过 48 小时未成功：报告 stale 原因；非日级来源使用各自频率。
- 价格事实数量突然大幅下降：产生候选异常，不自动解释为模型下线。
- API 无有效数据、连续 5xx、加载失败且旧版超出新鲜度预算：区分可用性与数据质量告警。
- 构建超过采集周期或持续超过基线预算、磁盘逼近保留版本所需空间：触发容量处理。

为每个规则定义触发、去重键、恢复条件和处理步骤。已有 GitHub Issue 通知可继续复用，避免每次失败新建重复 Issue；测试使用 mock/测试仓库，不向真实用户发送测试告警。新的通知渠道须有明确接收人与使用授权。

## 8D. 容量复核与升级判断

复用 AR-01 的 1×/5×/10×输入和相同机器，比较 AR-02/04/05/06/07 的结果。容量报告至少回答：

1. 在目标负载下，P95/事件循环/内存是否满足冻结预算？最先超预算的是哪一项？
2. 当前数据增长下，何时接近该边界？注明采样跨度和外推假设；样本不足不做精确日期预测。
3. 下一步是减少重复工作、增加索引、提高机器资源，还是需要数据库/worker？每个决定对应证据。
4. 如果迁移数据库，保留 datasetVersion、cursor、证据引用与备份恢复的最小设计是什么？本任务产出决策，不直接实施数据库迁移。

需要连续数据的趋势项可先标观察中，不必等数周才能交付采集功能；功能完成、趋势结论和线上效果分别标记。

## 验收标准

- [x] 一次请求可关联到实际 release/dataset；一次失败来源可关联到对应 run 和适配器。
- [x] 指标采集不在每个请求重复扫描全数据或同步写磁盘，开销经过同负载对比。
- [x] 模拟来源失败、数据加载失败、429、候选发布失败时规则正确触发并去重，恢复后状态正确。
- [x] 进程健康、数据就绪与数据新鲜度不会相互混淆。
- [x] 已有 Umami 埋点数量和字段不因本任务改变。
- [x] 容量报告使用可复现数据，包含测量限制及清晰的升级/暂缓结论。

## 发布与回退

先写结构化日志和本地汇总，再接入已存在的通知路径。采集和告警应可单独关闭，关闭不影响数据服务；日志有轮转和容量上限。只回退采集配置时不清理历史诊断证据，按明确保留期处理。
