REST 为三个各 60 请求的采样窗口，表中取并发 10 三轮最大值，不选择最快一轮；同时保留并发 1/30。原八类查询加 changes/prices 无匹配文本搜索，以覆盖扫描；MCP 60 次请求使用其契约 limit=30，REST limit=100。实际导入 GeoIP 模块并与 REST/MCP 共处测试进程。1×为真实数据，5×/10×只按固定 seed 扩大变化/条目/价格/证据并一致重映射 ID，模型目录不扩大，不模拟任意规模身份目录或真实到达率。

原始报告保存全部数据/轮次、源码（含递归 shared contract）和编译产物 SHA256、Node/系统/CPU/内存及 seed。峰值来自 Node resourceUsage().maxRSS；它覆盖整个子进程，包括合成数据生成、重复加载、worker、历史加载和额外 limiter fixture，不能直接视为单个真实服务实例的生产峰值。稳态 RSS 也受 V8 回收和前序加载影响。缓存 128 MiB 限制是原始集合字节而非 RSS；诊断和保留版本必须与进程内存一起评估。

1×实际历史版本首次加载 373.1 ms，持有历史对象时强制重新校验当前版 385.4 ms，之后 RSS 540.9 MiB；当前强制加载期间请求全部成功。三个规模重载的事件循环 max 为 12.7/12.8/14.6 ms，低于 50 ms；max 和吞吐窗口 P99 是不同统计量，原报告分别保留。

AR-01 同机冷加载中位 198.7/1087.0/2490.8 ms，当前为 397.9/1777.0/3680.4 ms。完整验证、worker 传递和索引增加了冷启动工作，不能宣称所有阶段都提速；收益是加载过程中保留旧版服务、无变化只读 manifest、避免主线程同步全量解析。AR-01 与当前查询集合、GeoIP 和峰值范围不同，不报告未经匹配的整体速度倍数。

同 1×负载诊断 off/on 并发 10 的三轮最大 P95 为 14.265/16.482 ms，loop P99 为 12.444/12.231 ms；开启状态没有丢弃或写失败。输出使用 discard Writable，覆盖序列化/排队，不测 journald 写盘或外部日志服务；不是严格随机交叉试验，不能把差值当作稳定常数。实际 server 另验证 enabled/disabled/unready、数据计数和敏感参数不进日志。

## 资源与升级条件

生产内存和 RTO 尚未冻结，本地达标不能替代服务器达标。先用正式候选在部署机器测量：单实例稳态、当前+最大可访问历史缓存、SIGHUP 验证、蓝绿两个槽位并存、启动 worker、服务日志和其他进程。预算应覆盖 `两实例实际最大 RSS + 系统/代理/其他服务 + 明确余量`；worker 已包含在实例测量时不重复相加。本地 1×整个子进程约 602 MiB、10×约 3107 MiB 只作保守规划参照；蓝绿不能按一个稳态实例估算。

| 启动条件 | 首先处理 | 后续改造必须保持 |
| --- | --- | --- |
| 相同目标负载连续窗口 P95>200 ms 或 loop P99>50 ms | 找具体筛选/扫描、补索引或减少重复排序；用同版本查询复验 | Decimal/价格条件、排序、窗口、撤回语义 |
| 实际加载/历史缓存/蓝绿内存接近已分配额度（建议 70% 开始复查，非自动扩容） | 收紧缓存、减少重复对象、资源升级；复测加载峰值 | 缓存淘汰仍可加载合同期历史版本 |
| 以上仍超预算，或开始多写入方/用户订阅等持久查询 | 独立规划 SQLite/PostgreSQL | 每版本不可变表/索引，cursor 固定版本+参数+排序键，共享签名密钥；原ID/证据/归档可对账；备份恢复与旧release独立启动 |
| 单次采集持续无法在调度周期内结束，或明确多调度者 | 先拆出慢来源与重试；确需持久调度再引入 worker/队列 | 单写入提交、run/attempt幂等、租约/恢复、失败不改观察时间 |
| 单实例实测吞吐不足或出现明确可用性目标 | 规划多实例和代理分流 | 同数据版本、CURSOR_SECRET、就绪门禁、全局/单客户端限流口径 |

目前单次完整标准构建约数分钟，使用 24 小时采集周期；暂无周期耗尽证据。构建日志提供阶段趋势的采集入口，真实 CI 连续分布待上线观察，不能据几个本地运行给出“持续变慢”的结论。

AR-06 原始快照在 14 个观测日平均约 9.14 MiB/日，只可条件外推存储流量；不同数据类别和内存对象膨胀不同，不由此预测何日达到 5×/10× API 容量。代码没有自动扩大缓存或删除历史。
